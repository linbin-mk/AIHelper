## ADDED Requirements

### Requirement: 会话自动创建
系统 SHALL 在用户发送首条消息时创建会话，并以用户消息截取作为标题立即渲染卡片到侧边栏。

#### Scenario: 欢迎页发送消息创建会话
- **WHEN** 用户当前在欢迎页（无活跃会话），在输入框中输入文本并发送
- **THEN** 系统创建新会话（生成唯一会话 ID，格式 `session_` + 时间戳），存储用户消息
- **AND** 会话标题设置为用户消息清理特殊字符后截取的前 15 个字符，`titleSource` 标记为 `truncated`
- **AND** 聊天区切换为该会话的消息视图，开始接收 AI 流式回复
- **AND** 侧边栏立即出现新会话卡片，显示截取标题

#### Scenario: AI 回复完成后卡片出现
- **WHEN** 会话卡片已在侧边栏展示（阶段1截取标题），AI 完成首条回复
- **THEN** 卡片保持原位不变，标题可能随后被 AI 精炼标题覆盖（阶段2）

#### Scenario: 已有活跃会话时发送不创建新会话
- **WHEN** 用户当前在某个会话中，发送新消息
- **THEN** 消息追加到当前活跃会话
- **AND** 不创建新会话

### Requirement: 手动创建会话
系统 SHALL 支持用户通过侧边栏「+ 新建会话」按钮清空聊天区并取消当前会话选中，不创建存储记录，并同步清空持久化的活跃会话 ID。

#### Scenario: 点击新建会话按钮
- **WHEN** 用户点击侧边栏顶部的「+ 新建会话」按钮
- **THEN** 聊天区切换为欢迎页状态
- **AND** 当前活跃会话取消选中（侧边栏取消高亮）
- **AND** `SessionManager.getActiveSessionId()` 返回 `null`
- **AND** 输入框清空，等待用户输入
- **AND** 不在 storage 中创建新会话，侧边栏不新增卡片

### Requirement: AI 自动生成会话标题
系统 SHALL 在用户发送首条消息后将用户消息清理截取为初始标题，并在 1 分钟延时后调用大模型 API 精炼标题。

#### Scenario: 发送消息后立即设置初始标题
- **WHEN** 用户在会话中发送首条消息
- **THEN** 会话标题立即设置为用户消息去除特殊字符后截取的前 15 个字符
- **AND** `titleSource` 字段标记为 `truncated`
- **AND** 启动 1 分钟延时定时器

#### Scenario: 定时器到期后 API 精炼标题
- **WHEN** 1 分钟延时定时器到期，且会话 `titleSource` 仍为 `truncated`
- **THEN** 系统发送独立的标题生成请求（非流式），prompt 包含用户问题和 AI 回复
- **AND** 生成结果返回后，会话标题更新为 API 返回的标题（不超过 15 字符）
- **AND** `titleSource` 字段更新为 `ai`
- **AND** 侧边栏卡片标题同步更新

#### Scenario: AI 在1分钟内完成时直接精炼标题
- **WHEN** AI 在 1 分钟延时定时器到期前完成首条回复
- **THEN** 系统清除定时器，立即用完整 AI 回复调用标题生成 API
- **AND** 生成结果返回后更新标题和卡片（同定时器到期场景）

#### Scenario: API 精炼失败保留初始标题
- **WHEN** 标题生成 API 调用失败
- **THEN** 系统不做任何处理，会话标题保持为阶段1截取的初始标题
- **AND** `titleSource` 保持为 `truncated`

#### Scenario: 多轮对话不重新生成标题
- **WHEN** 用户在已有标题的会话中继续对话
- **THEN** 会话标题保持不变
- **AND** 不启动新的标题生成定时器

#### Scenario: 用户点击停止取消定时器
- **WHEN** 用户在 1 分钟延时期间点击「停止」按钮终止 AI 回复
- **THEN** 系统清除当前会话的延时标题定时器
- **AND** 不再执行 API 精炼，截取标题即为最终标题

#### Scenario: 定时器到期时标题已被手动修改
- **WHEN** 1 分钟延时定时器到期，但用户已手动重命名了该会话标题
- **THEN** 不执行 API 精炼，保留用户手动修改的标题

### Requirement: 会话切换
系统 SHALL 支持用户在侧边栏点击切换会话，切换过程不丢失当前会话上下文。

#### Scenario: 点击侧边栏会话卡片切换
- **WHEN** 用户点击侧边栏中的会话 B 卡片
- **THEN** 聊天区切换展示会话 B 的完整消息历史
- **AND** 侧边栏中会话 B 高亮为活跃状态
- **AND** 输入框显示并聚焦
- **AND** 会话 A 的消息状态完整保留

#### Scenario: 切换时流式输出处理
- **WHEN** 会话 A 正在接收 AI 流式回复，用户点击会话 B
- **THEN** 聊天区切换展示会话 B，会话 A 的流式输出继续在后台接收
- **AND** 当用户切回会话 A 时，若流式输出未完成则继续展示
- **AND** 若流式输出已完成，展示完整回复

### Requirement: 会话删除
系统 SHALL 支持通过侧边栏会话卡片的右键菜单删除单个会话，以及通过列表底部的垃圾桶按钮批量删除选中的会话。

#### Scenario: 删除单个会话
- **WHEN** 用户右键点击侧边栏某会话卡片，选择「删除」
- **THEN** 弹出确认对话框：「确定删除会话「{标题}」？」
- **AND** 用户确认后，该会话从侧边栏移除并从存储中永久删除
- **AND** 若当前正在查看该会话，自动跳转到最近活跃的会话或欢迎页

#### Scenario: 批量选择删除会话
- **WHEN** 用户点击侧边栏会话列表底部的垃圾桶按钮
- **THEN** 弹出对话框展示所有会话（带复选框），支持全选/取消全选
- **AND** 用户勾选会话后点击「确定」，选中的会话被永久删除
- **AND** 若活跃会话被删除，持久化活跃会话 ID 被清空，聊天区重置为欢迎页

### Requirement: 会话重命名
系统 SHALL 支持用户手动重命名会话标题。

#### Scenario: 右键菜单重命名
- **WHEN** 用户右键点击侧边栏某会话卡片，选择「重命名」
- **THEN** 会话标题变为可编辑输入框
- **AND** 输入框自动聚焦并全选当前标题文本
- **AND** 用户输入新名称后按回车或点击外部区域保存
- **AND** 保存后标题更新，持久化到存储

#### Scenario: 空名称处理
- **WHEN** 用户重命名时输入空名称
- **THEN** 名称回退为原标题，不保存

### Requirement: 导出日志（侧边栏入口）
导出聊天日志的入口 SHALL 从顶部工具栏移至侧边栏会话卡片的右键菜单。

#### Scenario: 右键菜单导出
- **WHEN** 用户右键点击侧边栏某会话卡片，选择「导出日志」
- **THEN** 系统下载该会话的 JSON 日志文件，文件名格式为 `ai-helper-chat-{sessionTitle}-YYYYMMDD-HHmmss.json`
- **AND** 导出数据结构保持不变（meta + messages）

#### Scenario: 空会话导出
- **WHEN** 用户导出没有任何消息的会话
- **THEN** 仍下载 JSON 文件，messages 为空数组

### Requirement: 会话时间分组
侧边栏中的会话列表 SHALL 按最后活跃时间倒序排列，并按时间维度分组。

#### Scenario: 默认分组显示
- **WHEN** 用户拥有多条不同时间活跃的历史会话
- **THEN** 会话按时间分组显示：「今天」「昨天」「本周」「更早」
- **AND** 每个分组内有会话时显示分组标题，无会话时不显示该分组
- **AND** 同一分组内按最后活跃时间倒序排列

#### Scenario: 分组时间计算
- **WHEN** 系统渲染会话列表
- **THEN** 最后活跃时间在今天的会话归入「今天」分组
- **AND** 最后活跃时间在昨天的归入「昨天」分组
- **AND** 最后活跃时间在最近 7 天内的归入「本周」分组
- **AND** 其余归入「更早」分组

### Requirement: 会话搜索
系统 SHALL 在侧边栏搜索框中支持按关键词实时过滤会话列表，同时支持通过工具栏放大镜按钮和胶囊搜索按钮触发搜索聚焦。

#### Scenario: 搜索过滤
- **WHEN** 用户在侧边栏搜索框中输入关键词
- **THEN** 会话列表实时过滤，仅显示标题匹配的会话
- **AND** 匹配关键词在标题中高亮显示
- **AND** 搜索结果无视时间分组，统一按时间倒序排列

#### Scenario: 清空搜索
- **WHEN** 用户清空搜索框或点击清除按钮
- **THEN** 会话列表恢复为时间分组视图

#### Scenario: 通过放大镜按钮触发搜索
- **WHEN** 用户点击侧边栏工具栏中的搜索放大镜按钮
- **THEN** 若侧边栏已收起，先展开侧边栏
- **AND** 搜索输入框自动聚焦
- **AND** 搜索输入框右侧出现向左手指（👈）引导动画，左右弹跳 3 秒后消失

#### Scenario: 通过胶囊搜索按钮触发
- **WHEN** 用户点击胶囊中的搜索按钮
- **THEN** 侧边栏自动展开、胶囊隐藏
- **AND** 搜索输入框自动聚焦
- **AND** 搜索输入框右侧出现向左手指（👈）引导动画，左右弹跳 3 秒后消失

### Requirement: 会话持久化
系统 SHALL 将所有会话及其消息持久化到 chrome.storage.local，支持页面刷新后完整恢复。

#### Scenario: 刷新后恢复（有活跃会话）
- **WHEN** 用户刷新页面或重新打开插件，且存在活跃会话 ID
- **THEN** 侧边栏完整恢复所有会话列表和时间分组
- **AND** 该活跃会话自动选中并恢复其消息历史
- **AND** 所有会话的标题、消息、创建时间完整保留

#### Scenario: 刷新后恢复（无活跃会话）
- **WHEN** 用户刷新页面或重新打开插件，且活跃会话 ID 为 `null`
- **THEN** 侧边栏完整恢复所有会话列表和时间分组
- **AND** 聊天区展示欢迎页
- **AND** 无会话被选中（侧边栏不显示高亮）
