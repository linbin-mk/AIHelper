# ai-chat-panel

## 新增需求

### 需求：思考卡片在思考完成后保持可见并可折叠
当 AI 完成推理后（无论后续是否有工具调用），思考卡片应当保持在 DOM 中可见。思考完成后，卡片应当处于折叠状态，并带有可点击的展开/折叠按钮以查看完整的思考内容。

#### 场景：无工具调用 — 思考卡片保持折叠
- **当** AI 流式输出 reasoning_content 随后输出 content（无 tool_calls）
- **则** 思考卡片应当保留在 DOM 中
- **且** 思考卡片应当处于折叠状态
- **且** 点击展开按钮应当展开卡片并显示完整的思考内容

#### 场景：有工具调用 — 思考卡片保持折叠
- **当** AI 流式输出 reasoning_content 随后输出 tool_calls
- **则** 思考卡片应当处于折叠状态（仅显示标题"思考过程"）
- **且** 在工具执行期间，思考卡片应当保持折叠状态
- **且** 任何时候点击展开按钮都应当展开卡片并显示完整的思考内容

### 需求：工具调用卡片具有执行中状态和自动折叠功能
当 AI 调用工具时，工具名称、参数和结果应当显示在一个可折叠的卡片中，其生命周期为：执行中（展开，动态）→ 已完成（折叠）。卡片在创建时默认折叠，仅在工具执行中临时展开。

#### 场景：工具执行中 — 卡片显示实时"进行中"状态
- **当** AI 开始执行工具
- **则** 应当出现一个可折叠的卡片
- **且** 卡片应当处于展开状态（仅在执行期间）
- **且** 标题应当显示 "⚡ 调用 {name} ... 进行中"
- **且** 卡片正文应当显示工具参数（格式化 JSON）

#### 场景：工具完成 — 卡片自动折叠
- **当** 工具返回结果
- **则** 卡片标题应当更新为 "🔧 调用 {name}"
- **且** 卡片应当折叠（`tool-card-collapsed` + `▶` 箭头）

#### 场景：下一个工具开始 — 前一个工具卡片保持折叠
- **当** AI 开始调用新工具（序列中的下一个）
- **则** 前一个工具的卡片应当保持折叠状态（已经是折叠的，无需额外操作）
- **且** 点击折叠的标题应当再次展开它

#### 场景：单轮调用多个工具
- **当** AI 在单次响应中调用多个工具
- **则** 多个工具调用合并为一个分组卡片（参见 `tool-call-grouping` 规范）
- **且** 单个工具调用仍使用独立卡片

### 需求：聊天历史恢复思考卡片和工具调用卡片
当插件关闭后重新打开时，`renderChatMessages` 应当从存储的消息数据中重建思考卡片和工具调用卡片，工具卡片默认处于折叠状态。

#### 场景：从 reasoning_content 恢复思考卡片
- **当** 存储的助手消息包含 `reasoning_content` 字段
- **则** `renderChatMessages` 应当创建一个思考卡片元素来显示推理内容
- **且** 卡片应当处于折叠状态

#### 场景：即使存在 tool_calls 也恢复思考卡片
- **当** 存储的助手消息同时包含 `reasoning_content` 和 `tool_calls`
- **则** `renderChatMessages` 应当同时创建思考卡片和工具调用卡片（或分组卡片）
- **且** 思考卡片和工具卡片都应当处于折叠状态

#### 场景：从 tool_calls 恢复工具调用卡片
- **当** 存储的助手消息包含 `tool_calls` 数组（多个元素）
- **则** `renderChatMessages` 应当创建一个分组卡片（参见 `tool-call-grouping` 规范）
- **且** 对应的工具结果消息应当关联并在对应的子项中显示
- **且** 分组卡片和所有子项均处于折叠状态

#### 场景：从单个 tool_call 恢复独立工具卡片
- **当** 存储的助手消息包含 `tool_calls` 数组（仅一个元素）
- **则** `renderChatMessages` 应当创建一个独立的工具调用卡片
- **且** 卡片处于折叠状态

### 需求：未配置模型时输入交互检测
当用户尝试在聊天输入框输入或发送消息时，系统 MUST 检测大模型是否已配置（`apiBaseUrl`、`apiKey`、`modelName` 均非空）。若未配置，则展示悬浮提示引导用户前往设置。

#### 场景：输入框获焦时未配模型展示提示
- **当** 用户点击或通过 Tab 键切换到聊天输入框使其获得焦点
- **且** 大模型配置不完整（`apiBaseUrl`、`apiKey`、`modelName` 任一为空）
- **则** 系统在输入框上方展示悬浮提示框
- **且** 输入框设为禁用状态（不可输入文字）
- **且** 提示框内容包含说明文字和"前往设置"按钮

#### 场景：点击发送按钮时未配模型展示提示
- **当** 用户点击"发送"按钮或按 Enter 键尝试发送消息
- **且** 大模型配置不完整
- **则** 系统在输入框上方展示悬浮提示框（与获焦时相同的提示框）
- **且** 不发送消息

#### 场景：已配置模型时不展示提示
- **当** 用户点击输入框使其获得焦点或点击"发送"按钮
- **且** 大模型配置完整
- **则** 不展示悬浮提示框
- **且** 输入框正常可用
- **且** 点击发送时正常发送消息

### 需求：悬浮提示框展示与交互
悬浮提示框 SHALL 以气泡形式展示在输入框上方，包含引导文字和操作按钮。

#### 场景：提示框内容
- **当** 检测到未配置模型
- **则** 展示一个悬浮气泡，包含：
  - 警告图标或文字提示"尚未配置大模型"
  - 简短说明引导用户配置 API 连接信息
  - 一个"前往设置"按钮
- **且** 气泡位置在输入框上方，视觉上关联输入区域

#### 场景：点击"前往设置"按钮
- **当** 用户在悬浮提示框中点击"前往设置"按钮
- **则** 系统切换到设置 Tab
- **且** 自动定位到"供应商"面板（Provider 配置区域）
- **且** 消除悬浮提示框

#### 场景：提示框消除方式
- **当** 悬浮提示框处于展示状态
- **则** 以下任一操作应消除提示框：
  - 用户点击"前往设置"按钮
  - 用户点击提示框外部区域
  - 用户切换到其他 Tab

### 需求：已配置模型后可正常使用聊天
当大模型已配置完成，聊天输入框 SHALL 恢复为正常可用状态。

#### 场景：配置后返回聊天可正常输入
- **当** 用户在设置页面完成模型配置并手动切换回"AI聊天"Tab
- **且** 输入框获得焦点
- **则** 不再展示悬浮提示框
- **且** 输入框处于可用状态，用户可以正常输入和发送消息

### 需求：恢复的消息中正确渲染 Markdown
当恢复聊天历史时，助手消息内容应当渲染为 Markdown 格式（而非纯文本）。

#### 场景：恢复的助手消息中渲染 Markdown
- **当** `renderChatMessages` 处理包含 Markdown 内容（例如 `**粗体**`、代码块）的助手消息
- **则** 内容应当在设置 innerHTML 之前经过 `renderMarkdown()` 处理
- **且** 结果应当显示为格式正确的 Markdown

### 需求：聊天区布局适配双栏结构
聊天区 SHALL 从当前的全宽单栏布局改为右侧面板布局，左侧为会话侧边栏。

#### 场景：聊天区在双栏布局中
- **当** 用户打开 AI 聊天 Tab
- **则** 聊天区（消息列表 + 输入框）占据右侧主区域
- **且** 左侧为会话侧边栏
- **且** 消息输入框始终固定在聊天区底部

#### 场景：侧边栏折叠时聊天区扩展
- **当** 侧边栏折叠为图标模式
- **则** 聊天区宽度自动扩展填充可用空间

### 需求：工具栏简化
聊天区顶部工具栏 SHALL 移除「清空」按钮，仅保留侧边栏切换按钮和当前会话信息；「导出日志」移至侧边栏右键菜单。

#### 场景：简化后的工具栏
- **当** 用户打开 AI 聊天 Tab
- **则** 顶部工具栏仅显示侧边栏切换按钮和当前活跃会话标题
- **且** 不显示「清空」和「导出日志」按钮

## 已移除需求

### 需求：清空按钮
**原因**: 清空功能已完全移除。用户可删除会话后新建来实现类似效果。

### 需求：导出日志按钮
**原因**: 导出功能移至侧边栏会话卡片的右键菜单，属于会话级别的操作而非全局操作。

### 需求：聊天完成后触发记忆生成
系统 SHALL 在 `startAgentLoop` 完成最终回复保存后，异步触发记忆生成流程。

#### 场景：正常对话完成后触发记忆生成
- **当** `startAgentLoop` 中无 tool_calls 分支执行 `await saveCurrentMessages()` 后
- **则** 系统异步调用 `triggerMemoryGeneration(sessionMessages, getCurrentHostname())`
- **且** 该调用不 await，确保不阻塞 UI

#### 场景：生成记忆不阻塞发送状态
- **当** 记忆生成被触发
- **则** `setSending(false)` 在触发前已执行
- **且** 用户可立即发起新一轮对话

#### 场景：错误或取消时跳过记忆生成
- **当** 用户取消对话或 AI 返回错误
- **则** 系统不触发记忆生成

### 需求：点击 AI聊天 Tab 自动跳转到设置
**原因**: 静默跳转对用户无感知，交互不友好。改为在用户实际尝试使用聊天输入时提示配置。
**迁移**: 点击 AI聊天 Tab 始终展示聊天页面；配置检测移至输入框获焦和发送时触发。

### 需求：保存配置后自动跳回 AI聊天 Tab
**原因**: 自动跳转剥夺用户选择权。用户可能在设置页还有其他配置需要调整，不应强制跳走。
**迁移**: 保存配置后停留在当前页面不跳转；用户手动切换 Tab。
## Requirements
### Requirement: 聊天历史中恢复交互式工具调用卡片
当 `renderChatMessages` 从存储的消息数据中重建聊天视图时，SHALL 识别 `tool_calls` 中的交互式工具调用（`ask_user`、`request_auth`、`display_table` 可点击模式），并根据 Agent Loop 运行状态决定是否绑定交互回调。

#### Scenario: 从 tool_calls 恢复交互式 ask_user 卡片
- **WHEN** 存储的助手消息包含 `tool_calls` 数组，且 `function.name === 'ask_user'`
- **AND** `_isSending === true` 且 `_pendingInteraction` 匹配此工具调用
- **THEN** `renderChatMessages` SHALL 创建询问卡片，展示问题、选项、自由输入框
- **AND** 卡片绑定 `handleQuestionCard` Promise 回调
- **AND** 不创建通用工具卡片

#### Scenario: 从 tool_calls 恢复交互式 request_auth 卡片
- **WHEN** 存储的助手消息包含 `tool_calls` 数组，且 `function.name === 'request_auth'`
- **AND** `_isSending === true` 且 `_pendingInteraction` 匹配此工具调用
- **THEN** `renderChatMessages` SHALL 创建授权卡片，展示操作名称、详情、风险等级
- **AND** 卡片绑定 `handleAuthCard` Promise 回调
- **AND** 不创建通用工具卡片

#### Scenario: 历史交互工具调用以只读模式展示
- **WHEN** 存储的助手消息包含 `ask_user` 或 `request_auth` 工具调用
- **AND** `_isSending === false` 或 `_pendingInteraction` 不匹配
- **THEN** `renderChatMessages` SHALL 创建对应的只读卡片（按钮 disabled）
- **AND** 不创建通用工具卡片
