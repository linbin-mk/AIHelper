## Context

当前项目配置数据模型（`ai_helper_git_projects`）存储项目名称、Git 地址、鉴权信息和分支，缺乏业务描述字段。AI 聊天通过 `buildProjectContext()` 注入的项目摘要仅包含项目名称和文件数量，AI 无法获取用户对项目用途的说明。

本变更在项目配置中新增可选描述字段（≤100 字符），在 UI 表单中提供编辑入口，并在聊天上下文中自动注入。

## Goals / Non-Goals

**Goals:**
- 项目配置数据模型新增 `description` 字段（可选，最多 100 字符）
- 添加/编辑表单中提供描述文本框，带字数计数提示
- 项目卡片展示描述摘要
- AI 聊天上下文注入项目描述信息
- 存量数据兼容（`description` 字段缺失时按空字符串处理）

**Non-Goals:**
- 不改变 `description` 是否影响 AI 工具调用行为（仅作为上下文注入）
- 不支持 Markdown 或富文本格式（纯文本）
- 不提供项目描述的批量导入/导出

## Decisions

### 1. 描述字段存储方式
**决定**: 描述直接存储在 `chrome.storage.local` 的项目配置对象中（`ai_helper_git_projects` 数组的每个元素新增 `description` 字段）。

**理由**: 描述是项目配置的一部分，与项目名称、地址等字段具有相同的生命周期（跟随项目添加/编辑/删除），存储在同一个 JSON 数组中最为简单自然，无需额外存储键或 IndexedDB 表。

**备选**: 如果存储在单独的键中会引入跨存储查询和一致性维护的复杂度。

### 2. 输入控件选择
**决定**: 使用 `<textarea>` 而非 `<input type="text">`，限制 100 字符，旁边显示实时字数计数 `(n/100)`。

**理由**: 100 字符的描述可能包含多行语义信息，textarea 更适合用户阅读和编辑稍长的文本，也提供更好的视觉暗示这是一个"描述"而非简短的"名称"。

### 3. AI 上下文注入策略
**决定**: 在 `buildProjectContext()` 的每个项目摘要中追加描述内容，格式为 `项目名(文件数文件) - 描述内容`。

**理由**: 保持现有注入格式一致性，最小化 token 开销。有描述的项目注入描述，无描述的保持原样。不做额外截断——因为描述已在输入时限制为 100 字符。

## Risks / Trade-offs

- **[存储容量]**: 每个项目新增 ≤100 字符的纯文本，`chrome.storage.local` 配额（10MB）完全不受影响
- **[UI 复杂度]**: 项目卡片多一行描述显示，可能拉长卡片高度 → 通过截断显示（超过 30 字用 `...`）控制视觉效果
- **[令牌预算]**: 每个项目的描述最多额外消耗 ~100 tokens → 项目数量通常不多（≤10），影响可忽略
