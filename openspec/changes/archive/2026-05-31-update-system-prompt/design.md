## Context

当前 `i18n.js` 中 `systemPrompt` 翻译块定义了 AI 系统提示词的默认内容，包含 `role`（角色定位）和 `rule1`-`rule5`（5 条行为规则）。该内容通过 `agents-md-cache.js` 的 `buildAgentsMdContent()` 组装为 Markdown，首次使用时缓存到 IndexedDB，用户可在设置面板编辑并覆盖。

README.md 已将产品定位升级为"浏览器 AI Agent「小A」"，涵盖 11 个技能、27 个内置工具、知识库、记忆管理、工作产物等完整能力。当前系统提示词仅定位为"HTTP 请求分析助手"，与实际能力严重脱节。

## Goals / Non-Goals

**Goals:**
- 更新 `role` 文本，反映完整 Agent 能力而非仅 HTTP 请求分析
- 新增任务分类规则，让 AI 根据问题类型选择不同工具策略（通用知识 vs 页面功能 vs 项目代码）
- 新增技能激活规则，要求必须 `activate_skill` 后严格遵循
- 新增功能地图记忆优先规则
- 新增简洁回复风格规则
- 保留并微调现有规则（请求为空、并行工具、写操作授权、技能感知）
- 中英文同步更新，保持翻译质量

**Non-Goals:**
- 不改变 `agents-md-cache.js` 的缓存逻辑、组装逻辑
- 不改变设置面板的编辑/重置 UI
- 不新增 i18n key 或结构调整
- 不改变系统提示词的运行时拼接逻辑（仍由 chat.js 追加动态上下文）

## Decisions

### 决策 1：仅修改 i18n 翻译文本，不改代码逻辑

**选择**：直接修改 `i18n.js` 中 `systemPrompt` 对象的字段值。

**理由**：系统提示词的内容变更本质上是翻译文本变更，代码层面的缓存、组装、UI 编辑器均无需修改。这是最小变更、零风险的方案。

**备选方案**：新增独立的 i18n key 结构。被否决——当前 `systemPrompt` 结构已成熟，只需更新文本内容。

### 决策 2：在翻译中新增任务分类引导规则

**选择**：在 `rule` 集合中新增一条规则，明确区分三类任务：
1. 通用知识 → 直接回答
2. 页面功能 → 使用页面上下文工具和请求分析
3. 项目代码 → 使用代码搜索工具

**理由**：当前 AI 有时会在通用知识问题上不必要地探索页面或搜索代码，浪费轮次。明确分类可以提升效率和回答质量。

### 决策 3：强化技能激活规则

**选择**：将 `rule5` 从"你可以主动使用"改为"你必须调用 `activate_skill` 工具激活技能获取完整规则"。

**理由**：实际使用中发现 AI 有时会跳过 `activate_skill` 直接执行，导致技能规则未被加载。强化措辞确保合规。

### 决策 4：新增回复风格规则

**选择**：新增一条规则要求 AI 回复简洁直接。

**理由**：Agent 模式下 AI 常输出冗长的前言后语，浪费 Token 且影响用户体验。

## Risks / Trade-offs

- **[风险] AI 行为可能变化不稳定**：系统提示词变更后，AI 的行为模式可能改变，需通过实际使用观察效果 → **缓解**：变更范围小，仅调整文本描述，不改变工具或 API；可通过回退 i18n 文本快速还原
- **[风险] 英文翻译可能与中文不完全一致**：需确保中英文版本语义对齐 → **缓解**：基于中英对照编写，人工校对

## Migration Plan

1. 修改 `i18n.js` 中两处 `systemPrompt` 对象（zh-CN 和 en）
2. 用户下次打开面板时，若之前未手动编辑过系统提示词，`agents-md-cache.js` 将重新生成并缓存新内容（因为缓存基于语言 key，只要语言不变，已缓存的旧内容不会自动更新）
3. 需考虑已缓存旧内容的用户如何更新到最新版 → 在 `agents-md-cache.js` 增加版本号检测机制，或依赖用户手动"重置为默认"
