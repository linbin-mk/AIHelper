## Context

当前 `config.js` 实现在 `<div class="config-container">` 中始终显示编辑表单。保存后使用 `showSaveSuccess()` 展示"已保存，开始聊天"文字提示。需要将保存后行为改为：表单隐藏，卡片显示，提供双模式切换。

项目为 Chrome Extension (Manifest V3)，前端无框架，使用原生 DOM 操作 + 全局函数通信。

## Goals / Non-Goals

**Goals:**
- 保存流程改为「验证表单 → 联通检测 → 仅检测通过后才写入 storage + 切卡片」
- 联通检测失败时保持在编辑表单，展示错误信息（沿用现有红色提示），不写入存储
- 保存成功后表单替换为模型信息卡片，无需文字提示跳转聊天
- 卡片直观展示：API Base URL、Model Name、联通状态（绿色成功/红色失败）
- 卡片提供刷新按钮（右上角）和编辑按钮（右下角）
- 编辑模式下保存逻辑同上：联通成功→写存储→切卡片；联通失败→留表单
- 已保存配置的用户进入设置页直接看到卡片，自动检测联通性

**Non-Goals:**
- 不变更 `testConnectivity` 的请求逻辑和超时控制
- 不修改 chrome.storage 的存储结构
- 不影响聊天页配置检测逻辑
- 不新增配置字段

## Decisions

### 1. 保存流程：先检测后存储

**方案**：将 `saveModelConfig` 调用移到 `testConnectivity` 成功之后。流程：验证 → 联通检测 → 成功则写 storage + 切卡片；失败则留表单 + 显示错误。

**理由**：确保 storage 中只保存联通已验证通过的配置。用户不会遇到"配置已保存但永远连不上"的情况。

### 2. 双模式切换：CSS `display` 控制卡片与表单

**方案**：在 `#settings-provider` 内并排放置表单区域（`#configFormArea`）和卡片区域（`#configCardArea`），通过 `display: none/flex` 切换。

**理由**：项目无框架依赖，原生 DOM 操作最简单可靠。无需动态创建/销毁 DOM，状态自然保持。

### 3. 卡片刷新按钮：复用 `testConnectivity`，只更新颜色不涉及存储

**方案**：刷新时从 storage 读取配置，调用 `testConnectivity()`，根据结果仅更新卡片颜色和状态文字。不重新写 storage。

**理由**：刷新只是验证当前已保存配置的可用性，配置本身无变化。绿→红表示当前网络/服务异常，红→绿表示已恢复。

### 4. 页面加载行为：有配置→卡片+自动检测，无配置→表单

**方案**：`DOMContentLoaded` 时读取 storage。有配置 → `showCard()` + 自动执行 `testConnectivity()` 更新颜色；无配置 → `showEditMode()` 展示空表单。

**理由**：已保存过配置的用户进入设置页应能快速看到当前状态，而非重复编辑。

### 5. 国际化文案处理

**方案**：新增卡片相关 key（状态文字、按钮文字等），中英文各一份。使用已有的 `t()` 函数处理。

## Risks / Trade-offs

- [风险] 联通检测失败时不写入存储，用户修改配置后若网络抖动则需重试 → 可接受，避免存储无效配置
- [风险] 页面加载时自动检测可能增加 API 请求 → 可接受，仅在进入设置页且已有配置时触发一次
- [权衡] 卡片模式不显示 API Key（安全考虑），编辑模式下也不回显 → 与现有行为一致
