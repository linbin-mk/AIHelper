## Context

当前 README 写于项目早期迭代，内容与实际架构严重脱节。历经 8 天密集开发（60+ 已归档变更），功能、模块和开发工作流已发生根本性变化。README 需要完全重写而非局部修补。

## Goals / Non-Goals

**Goals:**
- README 准确反映第 8 天迭代的架构、功能清单、目录结构
- 新开发者通过 README 即可理解项目全貌和使用方法
- 架构图覆盖所有现有模块（含新增的 content scripts、AGENTS.md 缓存）

**Non-Goals:**
- 不修改任何代码文件
- 不新增功能或修改现有功能
- 不包含详尽的 API 文档（属于代码内注释范畴）

## Decisions

1. **完全重写而非增量修补** — 差异过大，增量修补会导致内容碎块化和不一致
2. **保持现有文档结构骨架** — 核心能力 → 架构 → 目录结构 → 安装 → 使用 → 技术栈 → 注意事项，符合开发者预期
3. **技能展示使用分类列表** — 参照 `skills/manifest.json` 和实际技能文件，按分类（Testing/Product/Development）分组列出 11 个技能
4. **架构图简化但完整** — 保留 ASCII 框图风格，但补充缺失的 content script 模块和 AGENTS.md 缓存
5. **移除致谢章节** — 非技术内容，不属于项目文档范畴

## Risks / Trade-offs

- README 会随后续迭代继续变化 → 定期维护，每次重大迭代后检查
- 中英文混合可能影响国际化体验 → 保持全中文，项目本身有 i18n 系统
