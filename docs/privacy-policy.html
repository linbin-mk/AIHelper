AI Helper 隐私权政策

最后更新日期：2026 年 6 月 5 日

本隐私政策说明了 AI Helper 浏览器扩展（以下简称"本扩展"）如何访问、处理和存储用户数据。我们承诺对用户透明，本扩展的源代码完全公开，欢迎审查。

核心声明：AI Helper 的开发者 不运营任何服务器，不接收、不存储、不传输用户的任何个人数据。所有数据处理均在用户的浏览器本地完成。开发者无法访问用户的对话记录、API 密钥、浏览数据或任何其他信息。

1. 数据访问与收集

1.1 网络请求监控

本扩展通过 Chrome webRequest API 和页面脚本拦截技术（猴子补丁 window.fetch 和 XMLHttpRequest）捕获网络请求信息，包括：

  • 请求的 URL、HTTP 方法、请求路径
  • 请求头（Headers）
  • 请求体（Request Body）和响应体（Response Body）
  • 响应状态码

用途：用于在扩展面板中向用户展示网络请求详情，以及作为 AI 对话的页面上下文提供给用户配置的 LLM API。

存储位置：浏览器内存（Service Worker 的 Map 缓冲区），每个标签页最多保留 100 条记录，标签页关闭时自动清除。

1.2 Cookie 访问

本扩展通过 Chrome cookies API 读取用户当前浏览标签页域名下的 Cookie 信息。

用途：用于在扩展面板中统计展示 Cookie 数量，帮助用户了解当前页面的 Cookie 使用情况。

存储位置：浏览器内存，不持久化。

1.3 页面内容采集

当用户使用 AI 对话功能时，本扩展可采集当前页面的以下内容：

  • 页面 URL 和标题
  • DOM 中的表单字段信息（字段名、类型、标签等）
  • 页面可交互元素信息（按钮、链接等）
  • 页面 HTML 源码（默认截取前 50000 字符）
  • 页面 JavaScript 源码（内联脚本或外部脚本 URL）
  • 页面 CSS 样式
  • localStorage 和 sessionStorage 中的认证令牌（Token/JWT）
  • DOM 中的 CSRF Token

用途：为 AI 对话提供页面上下文，使 AI 能够理解和分析当前页面。

存储位置：浏览器内存，对话结束后清除。认证令牌在展示前经过掩码处理（短令牌全掩码，长令牌仅保留首尾少量字符）。

1.4 用户配置数据

用户主动配置以下信息时，数据存储在浏览器本地：

  • API 密钥（API Key）— 明文存储于 chrome.storage.local
  • API 基础 URL 和模型名称
  • 自定义请求头配置（用于请求头注入功能）
  • Git 项目配置（含认证凭据）

用途：扩展功能运行所必需。

存储位置：chrome.storage.local（Chrome 扩展本地存储）。

2. 数据传输

2.1 发往 LLM API 的数据

本扩展的核心功能是将用户对话和页面上下文发送给用户自己配置的 LLM API 服务。发送的数据包括：

  • 用户输入的对话消息
  • 完整的对话历史（包括 AI 回复和工具调用记录）
  • 页面 URL、页面元素信息、网络请求摘要等页面上下文
  • 用户导入的知识库内容、记忆文件内容
  • 用户上传的附件文件内容

数据接收方：用户自行配置的 API 服务商（由用户设置的 API Base URL 决定）。AI Helper 开发者不参与、不中转、无法访问此通信过程。

隐私责任：数据发送到哪个 API 服务商完全由用户自己决定和控制。用户在配置 API 服务时应自行查阅该服务商的隐私政策。

2.2 数据上传至开发者

本扩展不向开发者发送任何数据。不存在遥测、崩溃报告、使用统计或任何形式的后台数据回传。开发者不运营任何接收用户数据的服务器。

3. 数据存储

存储位置存储内容

用户对存储数据的控制：用户可以随时在扩展中删除对话会话、清除文件缓存。卸载扩展将同时清除 chrome.storage.local 和 IndexedDB 中的所有数据。

4. 数据分享与披露

  • 不与开发者分享：开发者不接收任何用户数据。
  • 不与第三方分享：本扩展不包含任何第三方分析、广告 SDK 或数据共享机制。
  • 法律要求：如果法律强制要求披露数据，由于开发者不持有任何用户数据，实际上无法提供。

5. 数据安全

  • API 密钥以明文形式存储在 chrome.storage.local 中。用户不应在不可信的计算机或共享环境中使用本扩展。
  • 与 LLM API 的通信使用 HTTPS 加密（取决于用户配置的 API Base URL）。
  • 页面脚本拦截功能排除了飞书（feishu.cn）域名，以避免干扰企业协作平台的安全机制。

6. 权限声明说明

本扩展在 manifest.json 中声明以下权限，各权限的用途如下：

7. 儿童隐私

本扩展不面向 13 岁以下的儿童。我们不会故意收集儿童的个人信息。

8. 政策更新

我们可能会不时更新本隐私政策。更新后的政策将在本页面发布，并在扩展的 Chrome Web Store 列表页中更新链接。

9. 联系方式

如对本隐私政策有任何疑问，请通过以下方式联系：

AI Helper Privacy Policy

Last Updated: June 5, 2026

This privacy policy describes how the AI Helper browser extension ("the Extension") accesses, processes, and stores user data. We are committed to transparency — the Extension's source code is fully public and open to inspection.

Key Statement: The developer of AI Helper does not operate any servers and does not receive, store, or transmit any personal user data. All data processing happens locally in the user's browser. The developer cannot access users' conversation history, API keys, browsing data, or any other information.

1. Data Access & Collection

1.1 Network Request Monitoring

The Extension captures network request information via the Chrome webRequest API and page script interception (monkey-patching window.fetch and XMLHttpRequest), including:

  • Request URL, HTTP method, and path
  • Request headers
  • Request body and response body
  • Response status code

Purpose: Display network request details to users in the extension panel, and provide page context to the user-configured LLM API during AI conversations.

Storage: Browser memory (Service Worker Map buffer), up to 100 records per tab, automatically cleared when the tab is closed.

1.2 Cookie Access

The Extension reads cookie information from the current tab's domain via the Chrome cookies API.

Purpose: Display cookie count statistics in the extension panel to help users understand cookie usage on the current page.

Storage: Browser memory only, not persisted.

1.3 Page Content Collection

When the user uses the AI conversation feature, the Extension may collect the following from the current page:

  • Page URL and title
  • Form field information from the DOM (field names, types, labels, etc.)
  • Interactive element information (buttons, links, etc.)
  • Page HTML source (truncated to 50,000 characters by default)
  • Page JavaScript source (inline scripts or external script URLs)
  • Page CSS styles
  • Authentication tokens (Token/JWT) from localStorage and sessionStorage
  • CSRF tokens from the DOM

Purpose: Provide page context for AI conversations, enabling the AI to understand and analyze the current page.

Storage: Browser memory, cleared after the conversation ends. Authentication tokens are masked before display (short tokens fully masked, long tokens show only a few characters at the beginning and end).

1.4 User Configuration Data

When users manually configure the following, data is stored locally in the browser:

  • API Key — stored in plaintext in chrome.storage.local
  • API Base URL and model name
  • Custom request header configuration (for header injection feature)
  • Git project configuration (including authentication credentials)

Purpose: Required for the Extension's functionality.

Storage: chrome.storage.local (Chrome extension local storage).

2. Data Transmission

2.1 Data Sent to LLM API

The core functionality of the Extension involves sending user conversations and page context to the LLM API service configured by the user. Data sent includes:

  • User input messages
  • Complete conversation history (including AI replies and tool call records)
  • Page context such as page URL, element information, and network request summaries
  • User-imported knowledge base content and memory file content
  • User-uploaded attachment file content

Data Recipient: The API service provider configured by the user (determined by the user's API Base URL setting). The AI Helper developer does not participate in, relay, or have access to this communication.

Privacy Responsibility: Which API service provider data is sent to is entirely determined and controlled by the user. Users should review the privacy policy of their chosen API provider when configuring the service.

2.2 Data Uploaded to Developer

The Extension does not send any data to the developer. There is no telemetry, crash reporting, usage statistics, or any form of background data transmission. The developer does not operate any server that receives user data.

3. Data Storage

Storage LocationStored Content
Browser MemoryNetwork request buffers, page context collection data (cleared when tab is closed or extension goes idle)
chrome.storage.localAPI configuration, conversation session list, extension settings, custom request headers, Git project configuration, skill configuration
IndexedDBConversation file cache (source files, memory files, work artifacts, user-uploaded attachments)

User Control Over Stored Data: Users can delete conversation sessions and clear file caches at any time within the extension. Uninstalling the extension will clear all data in chrome.storage.local and IndexedDB.

4. Data Sharing & Disclosure

  • Not shared with developer: The developer receives no user data.
  • Not shared with third parties: The Extension contains no third-party analytics, advertising SDKs, or data sharing mechanisms.
  • Legal requirements: If legally compelled to disclose data, the developer cannot do so because no user data is held.

5. Data Security

  • The API key is stored in plaintext in chrome.storage.local. Users should not use the Extension on untrusted computers or in shared environments.
  • Communication with the LLM API uses HTTPS encryption (depending on the user-configured API Base URL).
  • The page script interception feature excludes the feishu.cn domain to avoid interfering with enterprise collaboration platform security mechanisms.

6. Permission Declaration

The Extension declares the following permissions in its manifest.json, each serving the purposes described below:

7. Children's Privacy

The Extension is not directed at children under 13. We do not knowingly collect personal information from children.
